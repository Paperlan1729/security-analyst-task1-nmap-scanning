PORT-BY-PORT SECURITY ANALYSIS

Port 22 (SSH - OpenSSH 8.9)
- What it does: Provides encrypted remote command-line access.
- Risk: Brute-force attacks, credential stuffing, or exploitation of outdated SSH versions.
- Recommendation: Disable password authentication, use SSH keys only, change default port if policy allows, enable fail2ban, keep updated.

Port 80 (HTTP - Apache 2.4.52)
- What it does: Serves unencrypted web content.
- Risk: Traffic can be intercepted (MITM). Vulnerable to web application attacks if the site is not hardened.
- Recommendation: Redirect all traffic to HTTPS, apply security headers, keep Apache and applications patched.

Port 443 (HTTPS - Apache)
- What it does: Serves encrypted web traffic.
- Risk: Lower than plain HTTP, but still depends on TLS configuration strength and application security.
- Recommendation: Use strong cipher suites, enable HSTS, monitor certificate validity, keep software current.

Port 3306 (MySQL)
- What it does: Database server accepting remote connections.
- Risk: High. Database exposure is a common path to data breaches. Brute-force or vulnerability exploitation can lead to full data compromise.
- Recommendation: Bind MySQL to 127.0.0.1 only, or restrict with firewall rules to application servers. Use strong authentication and least privilege.

Port 8080 (Alternative HTTP)
- What it does: Often used by application servers, proxies, or development tools.
- Risk: Frequently overlooked and may run less-hardened services.
- Recommendation: Restrict access via firewall, confirm necessity, apply same hardening as primary web services.

- Host is alive and running multiple network services.

- Web services (80/443) should be reviewed for proper TLS configuration and application security.
- SSH appears reasonably modern but should follow key-only authentication best practices.
